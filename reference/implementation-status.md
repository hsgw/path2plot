# 実装状況(path2plot)

このファイルは実装フェーズの進捗管理台帳。フェーズ分けは [SPEC.md](./SPEC.md) のFR番号(機能要件)に対応する。実装作業の前後にこのファイルを確認し、該当フェーズのステータス/メモを更新すること。

方針: 「パスの単純な分解→gcode出力→パスの最適化・円弧処理→塗りつぶし処理→書き順→ペン分割→仕上げ」の順でコア機能を先に作る。パスの単純な分解・gcode出力の時点では単一ペン(色分割なし)を前提とし、ペン分割は最後に追加する。実機(Prusa MK3S)テストは各フェーズの検証で随時行う。

各フェーズの「テストデータ」で参照するサンプルSVGは `fixtures/phaseN/` 配下に用意済み。ユニットテストからも同じfixturesを再利用できる。

## Phase 1: SVG読み込みと表示

**目的**: SVGファイルを読み込み、パースしてプレビュー列にそのまま描画できるようにする。ペン分割・色分けはまだ行わない。

**対象FR**: FR-1, FR-2, FR-3, FR-4, FR-5, FR-36

**主なタスク**

- [x] ファイル選択UIとDOMParserによるSVG読込
- [x] 対応要素判定(`path`/`rect`/`circle`/`ellipse`/`line`/`polyline`/`polygon`/`g`)と未対応要素のエラー化(FR-1/36)
- [x] `defs`/`metadata`/`style`要素、`display:none`/`visibility:hidden`要素の無視
- [x] transform(translate/rotate/scale/skewX/skewY/matrix)のflatten処理
- [x] ベジェ曲線(C/Q)の折線化、許容誤差のUI設定(FR-3)
- [x] SVG座標系→プリンタ座標系の変換(FR-4:プリンタY = (viewBoxのmin-y + viewBoxの高さ − SVG_Y) × スケール)
- [x] DPI/倍率のUI設定によるスケール(FR-2)
- [x] stroke/fillが`none`・透明、stroke-width=0の要素の除外(FR-5)

**ユニットテスト**

- [x] transform flatten(translate/rotate/scale/skewX/skewY/matrixの合成)
- [x] ベジェ曲線(C/Q)の折線化(許容誤差ごとの分割数・誤差)
- [x] SVG座標系→プリンタ座標系の変換式(FR-4、viewBox未指定時の挙動含む)

**成果物**: パース済みジオメトリをプレビュー列に単純描画(色分け・ペン分割なし)

**検証方法**: 複数パス・transform・ベジェを含むサンプルSVGを読み込み、正しい向き・縮尺で表示されること。未対応要素を含むSVGでエラー表示されること

**テストデータ**

- `fixtures/phase1/transforms.svg`: transform flatten(translate/rotate/scale/skewX/skewY/matrix)の確認用
- `fixtures/phase1/bezier.svg`: ベジェ曲線(C/Q)の折線化・許容誤差確認用
- `fixtures/phase1/viewbox-offset.svg`: viewBoxのmin-x/min-yが非ゼロの場合の座標変換(FR-4)確認用
- `fixtures/phase1/unsupported-elements.svg`: `image`/`text`/`use`/グラデーション/id参照されたclipPathを含む、FR-36エラー確認用
- `fixtures/phase1/ignored-elements.svg`: `display:none`/`visibility:hidden`(継承含む)・`defs`/`metadata`/`style`・未参照clipPathが無視されることの確認用
- `fixtures/phase1/excluded-strokes.svg`: stroke/fill=none・透明、stroke-width=0の除外(FR-5)確認用
- `fixtures/phase1/malformed.svg`: 意図的に不正なXML、パース不可エラー確認用

**ユーザーテスト**

1. `fixtures/phase1/transforms.svg` を読み込み、各図形が意図した位置・角度・拡縮で表示されることを確認する(nested transformが正しく合成されている)
2. `fixtures/phase1/bezier.svg` を読み込み、曲線が滑らかに(または許容誤差設定を変えて分割数が変化することを)確認する
3. `fixtures/phase1/viewbox-offset.svg` を読み込み、viewBoxのオフセット分だけずれずに正しい位置に表示されることを確認する
4. `fixtures/phase1/unsupported-elements.svg` を読み込み、`image`/`text`/`use`/グラデーション使用/id参照clipPathのそれぞれについて、該当要素を特定できるエラー表示が出ることを確認する
5. `fixtures/phase1/ignored-elements.svg` を読み込み、非表示要素・無視対象要素がエラーにならず単に描画されない(かつ正常なrectのみ表示される)ことを確認する
6. `fixtures/phase1/excluded-strokes.svg` を読み込み、除外対象の4要素が描画されず、正常なpathのみ表示されることを確認する
7. `fixtures/phase1/malformed.svg` を読み込み、パース不可エラーが表示され、可能な範囲で行/列等の位置情報が示される(取得できない場合はエラーメッセージ全文が表示される)ことを確認する
8. DPI/倍率設定UIの値を変更し、プレビュー上のサイズが連動して変わることを確認する

**ステータス**: 完了

**メモ**

- `src/core/`にmatrix・transform属性パーサー・パス(d属性)パーサー・円弧(A)→ベジェ変換・図形(rect/circle/ellipse/line/polyline/polygon)→パスコマンド変換・ベジェ折線化・座標変換・stroke/fill解決・DOMParser統合(`svgParser.ts`)を実装。円弧(Aコマンド)は本フェーズのfixtureでは未使用だが、実データ対応のため標準的なendpoint→center parameterizationで変換する実装を含めた
- ベジェ折線化は「制御点を最終mm座標系まで変換してから許容誤差(mm単位)で折線化する」方式とした。アフィン変換はベジェ曲線を不変に保つため、この順序で正確な結果が得られる
- Vitestは`src/core/**/*.test.ts`(node環境)に限定されているため、DOMParserに依存する`svgParser.ts`自体はユニットテスト対象外とし、要求されている3項目(transform flatten・ベジェ折線化・座標変換式)のみをテストした。`svgParser.ts`の統合的な動作はdevサーバー+Playwrightでfixtures/phase1配下の全7ファイルを読み込んで目視・自動検証済み(unsupported-elements.svgで期待通り5件のエラー、malformed.svgで行/列付きエラー、その他は0件のエラーで正しい形状・位置に描画)
- プレビューのフィット(拡大縮小・中心合わせ)は新規ファイル読込時のみ再計算する仕様とした。毎回自動フィットすると、DPI/倍率設定を変更してもプレビュー上のサイズが変化して見えず、ユーザーテスト8が満たせないため
  - **設計変更(2026-07-13、Phase3後のUI改善)**: 上記の「コンテンツのbounding boxにフィット」方式は、DPI変更のたびにプレビューの拡大縮小・位置がズレて見づらいという指摘を受け、「想定描画可能領域(FR-35のbedWidthMm/bedHeightMm)に固定フィットする」方式に変更した。ビュー(白い用紙枠の位置・大きさ)はベッドサイズ設定とコンテナのリサイズのみに追従し、DPI/倍率設定やSVG内容には一切依存しない。用紙枠からはみ出したストロークはそのまま枠外(アプリ背景色の領域)にはみ出して描画され、FR-38のはみ出し警告と視覚的に対応する。詳細はPhase3セクションの`PreviewPanel`関連メモ参照
- **既定DPI値の変更(2026-07-13)**: `App.tsx`の`DEFAULT_SETTINGS.dpi`を96→**72**に変更した。実運用で読み込むSVGはIllustrator書き出しが主であり、Illustratorの標準的な座標系(1 user unit = 1pt = 1/72インチ)に合わせることで、読み込み直後からDPI設定を手動で変更しなくても正しい実寸で表示・G-code出力できるようにするため(参考: `fixtures/user/gcode_test.svg`の実測でDPI=72相当と判明)
- rect要素の角丸(rx/ry)は仕様(SPEC.md)に明記がないため未対応(直角のみ)
- **UIリファクタリング(2026-07-13)**: エラー表示を`SettingsPanel`内のインライン表示から、画面上部に常時表示される`ErrorBanner`(新規`src/components/ErrorBanner.tsx`)に変更。設定列の開閉状態に関わらず視認できる(FR-41の警告表示パターンをFR-36のパース/要素エラーにも拡張)。手動で閉じられるが、エラー内容(signature)が変わると自動的に再表示される。FR-43のクリック/ホバー相互ハイライトやエラー文言の日本語整形は今回は対象外(見送り、要望があれば別途対応)

**目的**: サブパス単位のストロークへ分解し、SVG出現順のフラットなリストと基本のステップ実行プレビューを実装する。ペン分割・手動並び替え・端点結合はまだ行わない。

- [x] サブパス(M区切り)単位へのストローク分解(FR-11)

- [x] 開始点◯表示・描画方向表示(FR-24)

**ユニットテスト**

- [x] サブパス分解ロジック(M区切りの検出、開始点・方向の算出)

**成果物**: 出現順のストローク一覧とステップ実行プレビュー

**検証方法**: 複数サブパスを含むSVGで、ストロークが正しく分解されリスト・プレビューに反映されること

**テストデータ**

- `fixtures/phase2/multi-subpath.svg`: 1つの視覚的な線が複数のM区切りサブパスに分かれているケース
- `fixtures/phase2/many-strokes.svg`: ステップ実行プレビュー確認用(15本のストローク)

**ユーザーテスト**

1. `fixtures/phase2/multi-subpath.svg` を読み込み、リストに5本の独立したストロークとして表示されることを確認する(1本の線に見えても分解単位はサブパスであることの確認)
2. `fixtures/phase2/many-strokes.svg` を読み込み、リストがSVG出現順(横線が上から下、最後に縦線)に並んでいることを確認する
3. ステップ実行プレビューで「次へ」を繰り返し押し、1ストロークずつ描画が進むこと、開始点に◯が表示され描画方向が分かることを確認する
4. 「前へ」で1ステップ戻れること、「再生」で連続再生されることを確認する
5. ペンアップ移動経路(ストローク間の移動線)がプレビュー上に表示されることを確認する

**ステータス**: 完了

**メモ**

- サブパス(M区切り)へのストローク分解自体はPhase 1時点で`pathGeometry.ts`の`pathCommandsToPolylines`にすでに実装済みだったため、Phase 2ではこのロジックへのユニットテスト(`pathGeometry.test.ts`)追加とUI側(リスト・プレビュー)の実装が主な作業になった
- `ParsedStroke`に`color`(FR-26用、strokeが可視ならstroke色・そうでなければfill色)を追加。色解決ロジックは`colorResolve.ts`の`resolveDisplayColor`に実装(同ファイルはstyle属性パース・display:none判定・stroke/fill継承カスケードまで扱う内容だったため、2026-07-13に`styleResolve.ts`へリネーム)
- ステップ実行プレビューの状態(何本描画済みか)は当初`PreviewPanel`内のローカルstateだったが、**UIリファクタリング(2026-07-13)**で`App.tsx`にホイストし、`PreviewPanel`をcontrolled componentに変更(`StrokeListPanel`側でも同じstepを使って描画済み/未描画を表示するため)。新規ファイル読込時(`fitKey`変化時)のリセット先を「ステップ0」→「最終ステップ(全ストローク描画済み)」に変更し、読込み直後にプレビューが空に見える問題を解消。さらにステップを戻しても全体像を失わないよう、全ストロークを薄いアルファ値(0.2)で常時背景描画する「ゴースト表示」を追加。DPI/許容誤差等の設定変更でストローク数が変わった場合は範囲内にクランプするのみで、ステップ位置自体は極力保持する方針は変更なし(Phase2時点ではFR-39の手動編集リセット対象にステップ位置は含まれないため)
- **UIリファクタリング(2026-07-13)**: `StrokeListPanel`の各行に、現在のステップより後(未描画)のストロークを薄く表示する(`stroke-list-item-pending`、opacity0.35)機能を追加。パスリストとプレビューの対応関係を分かりやすくする軽量対応。クリック/ホバーでの相互ハイライト(FR-43)は今回は見送り
- 開始点◯・方向矢印はスクリーン座標(px)側で固定サイズ描画とした(mm座標系で固定サイズにすると拡大率次第で見た目のサイズが変わってしまうため)
- ペンアップ移動経路は赤の破線で、出現順に連続する2ストローク間(前のストロークの終点→次のストロークの始点)のみを結ぶ単純な実装。端点結合・貪欲法最適化はPhase 4/15で追加
- dev server + Playwright(`fixtures/phase2/multi-subpath.svg`・`many-strokes.svg`)で、5本/15本への分解・出現順表示・ステップ0→N→再生→15/15到達・前へ/次への単段階移動・赤破線ペンアップ経路の表示を目視確認済み
